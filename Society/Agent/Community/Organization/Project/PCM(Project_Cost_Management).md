## #has_/text_of_/abstract 

> **Project cost management** (PCM) is the dimension of project management 
> which aims to ensure that a project is completed within its approved budget. 
> 
> It encompasses several specific project management activities including 
> - estimating, 
> - job controls, 
> - field data collection, 
> - scheduling, 
> - accounting and 
> - design, 
> and uses technology to measure cost and productivity through the full life-cycle of enterprise level projects.
> 
> According to the Project Management Body of Knowledge (PMBOK), 
> PCM's primary concern is the cost of the resources needed to complete the project. 
> 
> However, PMBOK also notes that PCM should also consider the 
> impact of project management decisions on customers' wider or life-cycle costs 
> such as the use of the building or IT system generated by the project.
> 
> Beginning with estimating, a vital tool in PCM, 
> actual historical data is used to accurately plan all aspects of the project. 
> 
> As the project continues, job control uses data from the estimate 
> with the information reported from the field 
> to measure the cost and production in the project. 
> 
> From project initiation to completion, project cost management has an 
> objective to simplify and cheapen the project experience.
> 
> This technological approach has been a big 
> challenger to the mainstream estimating software and project management industries.
>
> [Wikipedia](https://en.wikipedia.org/wiki/Project%20cost%20management)  


## Simple Demo Calculation 

### Assumptions

- Project is built from Elements/Increments of the same size in Cost 
- Elements interact and this needs to be tested with every change 
- Compilation always requires the rebuild of the whole System 
- Testing in the worst case requires a full regression test after each Increment 

#### Full Compilation and Testing 

means that the differential Cost C grows at least with the total System Size S: 

S = Sum dS

dC / dS = c1 + g * S  = c1 + g * Sum(dS) 

Differentiation yields 
d²C / dS² = g  

Integrating this twice yields a quadratic Cost Function: 

C = c0 + c1 * S + * g * S²/s

With n increments of size dS (S = n·s), 
and the k-th increment costing g·(k * dS) * dS for rebuild and retest:

C = g * dS² * (1 + 2 + … + n) = g * dS² * n(n+1)/2 = g/2 (S² + dS * S)

#### differential Compilation and Testing 

can optimally make the cost linear: dC = g * dS  


#### increasing Complexity for Testing 

On the other hand if the binary combination of components increases the Testing Effort 
to grow quadratically, then the Cost becomes cubic. 
can optimally make the cost linear: dC = g * S²  => C = g * S³ / 3

If you also need to consider ternary and higher Combinations of Components, 
the relevant Powers become ever larger!
